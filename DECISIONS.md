# DECISIONS

Choices that could be defended either way. Format: decision, options, why, what would reverse it.

## D-01 Storage: one SQLite file, rebuilt from the exports on every build
- **Options:** (a) SQLite, (b) Postgres, (c) vector store, (d) in-memory pandas.
- **Chosen:** SQLite, with `python cockpit.py build` deleting and recreating it.
- **Why:** the exports are the record of truth and three more drops are coming; a deterministic rebuild means there is no hand-edited state to drift. Zero setup satisfies "one-command setup". Data is tiny (hundreds of rows).
- **Cost:** no incremental updates. Fine at this scale.
- **Reverse if:** data grows past ~1M rows or we need concurrent writers.

## D-02 Data model: source -> typed tables -> aliases -> findings
- Every row keeps `src_ref` (file!row) so any answer can cite it.
- `alias` table keeps every spelling ever seen with confidence and where it was seen; nothing is silently merged (see Sapphire/Saphire, A-10).
- `claim` holds the curated transcript statements with the verdict; `finding` holds computed issues.
- Free text (transcripts, emails, board PDFs) sits in `document`/`message` for fallback search.
- **Reverse if:** Day 3 Jira/git data makes a graph (tickets, commits, people) the main query shape.

## D-03 Cockpit answers are assembled from SQL, not generated by an LLM
- **Options:** (a) LLM with retrieval, (b) deterministic handlers, (c) hybrid.
- **Chosen:** deterministic handlers returning `{answer, cites, confidence, caveats}`.
- **Why:** the judging weights "true against the data room, cites sources, admits what it doesn't know". With handlers every number is a query result and unknown questions fall through to an honest "I don't have that".
- **Cost:** narrow question coverage; new question types need new handlers. Mitigated by the keyword fallback that shows related records without interpreting them.
- **Reverse if:** the CEO's final questions are mostly open-ended; then add an LLM that may only quote handler output.

## D-04 Agents: LLM persona when a key exists, grounded offline mode otherwise
- Work facts are injected from the DB at call time; private life and voice come from `personas.json` and are all logged as assumptions (A-P##).
- Memory is a per-agent JSONL transcript in `data/memory/` (simple, inspectable, deletable).
- **No payroll data ever enters an agent's context**, so leaks are structurally impossible rather than prompt-dependent.
- Data goes to an external API only if the user sets `ANTHROPIC_API_KEY`; default is offline.
- **Reverse if:** memory needs summarising across weeks (stretch: living agents).

## D-05 What the cockpit refuses to answer
1. **Individual pay** (CFO rule, T2). It gives totals only. This is a pushback on the CEO's "ask anything".
2. **Attrition rate**, until leaver data exists (Keka export has current staff only).
3. **Anything with no record**: returns "I don't have a record" with confidence None.
4. **Cause claims** (e.g. why AWS rose): it shows the trend and says cause is unknown.
5. **Single burn or ARR figure as certain**: always shows the source and the conflicting spoken number.

## D-06 Trust order when sources disagree
exports > board PDFs > email > transcripts, **except** where the export is known to be partial (GL is "selected cost centres"; Keka excludes contractors), then say so. Transcripts supply intent and context. Captured in TRANSCRIPT_NOTES.md.

## D-07 Release gating with `--as-of`
Files in later-day folders are ignored until their day (or until `--as-of` says otherwise). This keeps the Day 1 demo honest and gives "what did we know on date X" for free.

## D-08 Which 14 people become agents
Everyone in Engineering, Finance, People & Ops and Marketing (the brief's four teams) is exactly 14. CEO, Sales and Support stay as data only.

## D-09 UI and stack
Stdlib `http.server` plus one HTML file, Python 3.13, deps only `openpyxl` and `pypdf`. Chosen so a reviewer can read every line and so one command sets it up. A framework would add weight without adding judgement.

## D-10 Severity scoring in the worry view
3 = act now, 2 = look soon, 1 = FYI, assigned by me per rule. It is a judgement, so the view says so. Rahul's overpayment and the Atlas slip are 3 because one has a real person owed an answer and money out the door, and the other is the CEO's stated top concern.
